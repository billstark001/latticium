## Correctness and design changes

- Exact replacements now apply `target.using` to concrete post-break placement proposals before breaking. A live regression reproduced the previous behavior: a dirt-only hotbar could remove a stone source even when `using` allowed only stone. The corrected fixture preserves its source and submits no actions.
- Receipts compare the actual authoritative packet payload with the submitted expected state and visible state. Previously, local break prediction could hide a server packet changing the block to dirt; advancing a revision while the visible state was predicted air falsely confirmed the break. A conflicting packet now terminates the receipt and stops continued destruction. Initial-state packets, unrelated positions, evicted history and refresh-only hints cannot prove confirmation.
- Native retries increase planning work from 128 to 256, 512 and at most 1,024 node expansions per tick, including diagnostic searches. Each retry uses fresh facts and a fresh oracle/search. Only bounded scheduling metadata persists. This handles paths above the previous fixed slice without retaining stale native prediction inputs. Paths beyond the cap remain deferred; this is not unrestricted cross-tick frontier reuse.
- Planner material/risk cost overflow now defers rather than proving NoPlan. Action counts outside the remaining policy are rejected before addition. This prevents an arithmetic limitation from authorizing destructive fallback.
- `ClientPlanning` owns native search/fallback policy, while `ClientCandidates` owns membership, frozen target, confirmed partial state and retry scheduling. Candidate removal no longer scans a separate list. There is still no independent candidate-capacity limit; large loaded scopes need streaming scheduling with fair discovery and backpressure.
- Equal consecutive immutable multi-column capture cells share storage. Every requested native fact is still read. One local 26.3 comparison reduced full-section allocation from 613,728 to 484,368 bytes (about 21%), and broad radius-16 allocation from 11,162,016 to about 7,630,359 bytes (about 32%). State-only capture remained 36,064 bytes. These are allocation observations, not universal timing guarantees; a broad 48³ capture can still exceed a frame budget.
- Bridge revision tokens include source metadata modification time and the unsaved-change flag alongside placement identity. The placement UUID alone is not a content revision. Once a changed/removed placement is observed, the old session stays invalid even if its old metadata returns. Fresh sessions can recover. Direct container edits that fail to advance source markers remain an explicit limitation.
- Player-influence invalidation visits the smaller of the intersecting section range and the actual finite section index. Coordinate-edge coverage verifies clipping and coalescing without wrapping positions.
- Automatic activation always captures its player anchor, including for `all()` and fixed-coordinate predicates whose expression metadata otherwise needs no player facts. Without that anchor, the activation tracker silently deferred every sample. A rejected while-triggered START now resets its active flag and can retry when the missing selection appears; enter-triggered START keeps its consumed edge.
- Temporary hotbar-slot exhaustion is a deferral, preserving the confirmed intermediate state and frozen target for fresh replanning. Survival snow stacking previously dropped its candidate at three layers after two items were consumed, so a one-item replenishment could not finish the fourth layer.

MineDriver now reads native loading issues, fails promptly with `STARTUP_WARNINGS`/`STARTUP_ERRORS`, and records the issues with failure UI/screenshot evidence. `acceptedStartupWarnings` permits exact affected-mod/key pairs after diagnosis; every issue must be an accepted warning and errors never proceed. The Latticium wrapper exposes only the diagnosed Cloth metadata warning through `-AcceptClothLogoWarning`. Default behavior still rejects it.

MineDriver also returned from world creation as soon as player/level existed while `LevelLoadingScreen` remained open. The first native F8 event was then ignored. World creation and connection now require loading-screen and resource-overlay dismissal. Real singleplayer UI reruns cover the corrected boundary; dedicated-server connection remains unvalidated.

The startup smoke wrapper now asserts the native title screen in isolated MineDriver sessions and validates fresh complete reports. It no longer treats sound-engine logs as menu readiness. Gameplay checks keep a bounded action transition history in `action-trace.txt`. Read-only fixture loads are spread across client callbacks instead of parsing every source schematic in one callback; an individual source-mod file load remains synchronous.

The pinned Forgematica stack reports the same development metadata warning for seven additional mod IDs. `-AcceptKnownLogoWarnings` accepts only the diagnosed fixed list and issue key, including Cloth Config; the narrower Cloth-only switch remains available. Unknown issues still fail. After warning acceptance, a separate real startup race failed in MaFgLib 0.5.3: parallel NeoForge mod constructors called its unsynchronized initialization-handler `contains`/`add` pair, corrupting the `ArrayList`. The bridge now wraps that original method in an instance lock. Native run `1792083104758-275d5205-802b-45de-a810-a9a206bd9409` passed startup, 128 concurrent registration calls for 32 distinct handlers with no losses/duplicates, cleanup, full gameplay, all real fixtures and four-language UI. No loader thread-limit workaround is enabled.

That loader-handled failure also exposed a MineDriver startup hang before any completed frame. The driver now detects fresh native client crash reports in its isolated run directory and fails with `STARTUP_CRASH`, rather than depending on an uncaught exception or the full watchdog. Old seeded reports are ignored. Deterministic unit and forked-client coverage verifies the report path; the simulated client deliberately never renders a frame.

Two intermittent probe failures were traced to natural dirt-to-grass growth, not phantom placements. Read-only inspection of both failed saves found `grass_block` at the previously placed dirt position. Exact-state fixtures now set and verify `random_tick_speed=0` in their disposable worlds and log the condition. Explicit authoritative third-state/interruption tests still exercise external changes. Source schematic hashes, sizes and modification times are checked before and after matrix runs, including failures.
