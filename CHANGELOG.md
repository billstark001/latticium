## [0.0.2] - 2026-10-06

### Added

- Reproducible development gameplay probes for all seven targets, including read-only real-schematic fixtures with before/after SHA-256 verification.
- The pure planner exposes bounded resumable search over frozen inputs, with a retained-state cap.
- Native task controls and a diagnostic page, with rebindable controls and a small task HUD.
- Shared Cloth Config / AutoConfig settings, bundled for Fabric and NeoForge.
- Optional Fabric Mod Menu integration and a NeoForge built-in mod-list settings entry.
- English, Simplified Chinese, Traditional Chinese, and Japanese UI translations.
- Stop-all control that cancels the current task and suspends automatic activation until restored.
- Finite fill, replace, and clear jobs with client commands, saved selections, and schema-1 profiles.
- Typed, read-only DSL with bounded section queries, profile preview, and opt-in activation.
- Optional Litematica bridges for Fabric 26.2/26.3 and a Forgematica bridge for NeoForge 26.2.
- Continuous job refresh, manual refresh mode, and `/latticium refresh`.
- CI and release assembly for four main mods and three optional bridges.

### Changed

- Dense immutable fact windows, state palettes and exact per-column spatial masks reduce section capture work. Native state decoding parses canonical properties directly instead of enumerating every possible state.
- Consecutive neighbor unions deduplicate reachable offsets; mixed neighborhood expressions memoize graph nodes under a bounded evaluation budget.
- Optional immutable target windows reduce repeated blueprint metadata reads. All three schematic bridges share session, bounds and overlap checks.
- Finite scopes support shifted and adjacent finite predicates, deduplicate boxes, union overlapping scan domains and bound intersection/grouping work. A lint check guards against direct client-level chunk residency queries.
- Bound expressions expose fact dependencies, allowing section scans, activation samples and material rechecks to capture only requested columns. Candidate planning captures a local window instead of an entire section.
- Exposed immutable client/job snapshots for UI consumers, keeping partial scans, pending confirmations, continuous monitoring, and action-budget exhaustion distinct.
- Fabric development runs are generated by Loom and use Gradle's Java 25 launcher.

### Fixed

- Quick replacement can select a verified plain-block target before breaking the old block. Unverified post-break placement, fluid-containing sources and directly coupled multi-block structures defer without destructive fallback.
- Native capabilities retain their world identity; independent jobs end on world exit, and closed or cancelled gateways reject further submissions. Blueprint session metadata no longer retains disconnected worlds or removed placements through strong references.
- Server tag updates invalidate registry-bound tasks and automatic bindings while already submitted actions settle. A localized message explains why a manual task stopped.
- Named selection snapshots copy their bounds lists; event refresh uses expanded bound dependencies rather than losing declaration/function reads.
- The quick fill command includes cave air and void air as well as normal air.
- Hypothetical rule guards no longer reuse distant stale light, fluid or solidity facts.
- Repeated blueprint selection enumeration cannot rebase an existing session, and subregion iteration order does not invalidate it.
- Singleplayer preferences use the save directory instead of a non-unique display name. Corrupt trailing selection entries and duplicate normalized catalog IDs are rejected.
- Client and blueprint reads now check the actual chunk cache, preventing unloaded positions from being treated as known air by the client level’s permissive chunk query.
- A replacement retains its frozen target after a confirmed break even when the original source predicate no longer matches during refresh or follow-up submission.
- Client launch tasks no longer inherit an unintended Java 21 runtime from local IDEA settings.

### Compatibility and upgrade notes

- Requires Minecraft 26.2 or 26.3 and Java 25. Releases contain four main JARs (Fabric/NeoForge for both versions) and three optional bridges (Litematica on Fabric 26.2/26.3 and Forgematica on NeoForge 26.2). There is no NeoForge 26.3 blueprint bridge.
- Local-world preferences now use the save directory. Older display-name-based files are retained but not automatically applied; reload profile JSON, recreate selections and explicitly enable automatic profiles in the intended save.
- Server tag/datapack reload stops a manual task using old bindings; restart it to use the new tags. Enabled automatic profiles bind again on their next activation sample. Already submitted actions still settle.
- Destructive exact replacement currently proves plain property-free targets on reachable plain full-block supports. Fluid-containing or directly coupled multi-block sources and unverified property-sensitive replacements defer before breaking. Survival, dedicated-server and ordinary modpack acceptance remain incomplete.
- Native planning remains synchronous; full host revisions and native search continuation are still open work. Large candidate collections and broad legacy/custom halo captures need further memory/frame-budget acceptance.

### Validation

- Formatting, strict Java compilation, 237 ordinary JVM tests, five official-data tests and all seven distributable builds passed locally. GitHub CI also passed the core checks and seven distributable targets.
- Seven development clients passed in-world checks for requested fact columns, unloaded-cell Unknown, exact state decoding, confirmed plain-block fill/replacement, action budgets, conservative breaking and lifecycle/receipt handling. All 32,366 native states in 26.2 and 35,723 in 26.3 round-tripped through the codec.
- Each blueprint bridge loaded 53 real schematics read-only and checked rotated/mirrored target reads. Source hashes, sizes and modification times remained unchanged, including a deliberate audit-timeout test.
- Development probes are excluded from shipped JARs. These checks do not establish complete survival/server/modpack acceptance; launch conditions, measurements and remaining cases are recorded in the [validation record](https://github.com/billstark001/latticium/blob/v0.0.2/docs/26.2-26.3-validation.md).
